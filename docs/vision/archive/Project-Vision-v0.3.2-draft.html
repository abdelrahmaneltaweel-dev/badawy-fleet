2) المتطلبات (ثابتة حتى الآن)

  • الأسطول: 65 عربية (منهم عربيات نقل بنقلات، والباقي مشاوير). المستخدمين: 15–20 بأدوار.
  • كل حاجة مجانية ومستدامة، من غير كارت ومن غير أي احتمال فاتورة.
  • واجهة على GitHub Pages، وCRUD كامل، وإضافة ميزة لاحقًا تكون سهلة.
  • الريبو عام؛ الأسرار والبيانات مستحيل تتسرب.
  • Google Sheets يفضل نسخة احتياطية لو الموقع وقع.
  • لينك واحد وصفحة واحدة (SPA): كل مستخدم بحسابه يشوف حاجته بس؛ قابلة للتثبيت كـ PWA؛ متجاوبة على كل الشاشات.
  • كل حاجة تتدار من المنصة مش من الكود: مستخدمين، صلاحيات، سائقين، عربيات، أنواع عربيات، أنواع نقلات، قوائم اختيارات.

2-ج) مبادئ التشغيل

  • Config as Data: إضافة وتعديل وحذف مستخدم أو سائق أو عربية أو نوع أو اختيار من المنصة. الحد: خوارزمية تحليل جديدة تمامًا أو ميزة جديدة = كود.
  • الإدخال بالنيابة: الـ Super Admin يقدر يدخل أو يعدّل أي بيان أو رد مكان أي مستخدم مؤقتًا، بسجل واضح.
  • الإشعارات: داخل المنصة (عدّاد معلّق)، وخارجها واتساب يدوي بروابط wa.me بضغطة من الأدمن، والرابط يفتح الاستفسار مباشرة. الاتصال بالسائق عبر tel:.
  • SPA بلينك واحد: دخول، وقائمة تتبني من الصلاحيات، وتحميل كل شاشة عند الدخول عليها فقط (hash routing).
  • PWA: تثبيت على أندرويد وآيفون، وخزن هيكل التطبيق فقط مع شريط «نسخة جديدة»؛ إدخال بدون نت عبر Firestore offline (بعد الاختبار S-7). رفع صور خارج النسخة الأولى (Storage يحتاج Blaze). النشر على المتاجر خارج المجاني.
  • متجاوب بالكامل: mobile-first، الجداول الكبيرة بطاقات على الموبايل، RTL، فاتح/داكن.

2-د) داشبورد Super Admin (الترتيب متفق عليه)

  1. حالة الأسطول الآن: Online / Offline / واقفة، مقسّمة جرار / نقل / ملاكي.
  2. مشاكل GPS المفتوحة: المدة، وأزرار اتصال وواتساب للسائق.
  3. استفسارات منتظرة رد (سائقين، مدير الخلاطة، أمن الجراج).
  4. نقلات أمس للجرارات الـ 10 مع المطابقة الثلاثية (GPS ↔ بيان الخلاطة ↔ بيان الجراج) وأي فروق.
  5. مشاوير أمس لعربيات النقل والملاكي.
  6. محفظة Petro وطلب العهدة المعلّق.

2-هـ) طلب العهدة (Petro) — بدون ربط API

Petro App ليه API مدفوع، فمش هيتربط. المنصة بتحاكي وحدة الشيت الحالية: تحليل ملفين من Petro (تقرير الوقود + كشف الحساب) وتجهيز صفحتين للطباعة (A4، RTL).

  • الدورة: إنشاء الطلب (المبلغ يكتبه الـ Super Admin يدويًا) ← معلّق ← تاني يوم تظهر بطاقة «اتوافق عليه؟» ← موافق أو مرفوض. المرفوض: رفع ملفين جداد وطلب جديد مرتبط بالقديم (محاولة 2، 3…).
  • التقارير (شهر/سنة): عدد الطلبات، المرفوض واللي اتعمل تاني، المقبول من أول مرة ونسبته، وإجمالي المبالغ.
  • الملفات: لا تتخزن (Storage يحتاج Blaze). بتتخزن البيانات المحلّلة، والطباعة بتتولّد منها.
  • رصيد المحفظة وتنبيه 25 ألف: لو كشف الحساب فيه رصيد جاري (يتأكد من نموذج فعلي).

2-ز) مصدر البيانات: Traccar

  • Traccar على سيرفر داخلي للشركة، والوصول عبر الـ API فقط، ويحتفظ بتاريخ المسارات سنة. فنافذة إعادة الحساب من الخام = 12 شهر (تتماشى مع احتفاظنا بتفاصيل الوقفات).
  • مدة الاحتفاظ إعداد على سيرفرهم مش في إيدينا؛ فنعتمد على بياناتنا المحسوبة لما بعد السنة، ونبلّغ لو اتغيّر الإعداد.
  • إعادة حساب كمية كبيرة (65 عربية × شهور) بتتعمل على دفعات متباعدة علشان ما نضغطش سيرفر الشركة.
  • يُطلب من مسؤول السيرفر مستخدم Traccar قراءة فقط بتوكن للـ Worker.

4) المعمارية المقترحة

ليه اتغيّرت عن 0.1.0؟ مع 65 عربية: حصص Apps Script العادي (90 دقيقة triggers/يوم، 20 ألف UrlFetch/يوم، 30 تنفيذ متزامن) هتبقى العنق. وGitHub Pages عام فمينفعش نحط عليه بيانات حية. وTraccar على HTTP فالمتصفح مينفعش يكلمه.

5) الأمان والريبو العام

  • ريبو جديد من الصفر؛ القديم يتأرشف خاص. لو فيه أسرار اتحطت قبل كده: تغيير توكن Traccar.
  • أسرار في GitHub Secrets وScript Properties فقط. عنوان Traccar (حاليًا ظاهر في main.gs) يتنقل لـ Secret.
  • ممنوع في الريبو: إحداثيات المواقع الفعلية، أرقام الأجهزة، أرقام واتساب/إيميلات، توكنات، أي تصدير بيانات.
  • Firestore Rules: رفض الكل كأساس + صلاحية لكل دور؛ تسجيل ذاتي مقفول؛ الإدارة تنشئ المستخدمين.
  • Secret Scanning + Push Protection + pre-commit + .gitignore.

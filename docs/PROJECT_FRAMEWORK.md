# إطار عمل المشروع · Badawi Fleet Platform

> الملف ده **حي**: بيتحدّث بعد كل مهمة. أي Claude جديد (من غير ذاكرة) يبدأ منه، مع `docs/HANDOFF_PROMPT.md`.
> المرجع التصميمي والقراري: `docs/vision/Project-Vision-v1.0.0.html` (مجمّد). التنفيذ هنا.

## 0. إزاي تستخدم الملف
1. اقرا القسم 1 (الثوابت) والقسم 2 (الحالة) والقسم 3 (الخطوة التالية).
2. اشتغل على **مهمة واحدة** في المرة، من الجدول (القسم 4)، بترتيب المراحل والاعتماديات.
3. لما تخلص، طبّق **بروتوكول التحديث** (القسم 5) وسلّم الملف المحدّث للمالك.
4. قرار جديد = ADR + سطر في سجل القرارات + إصدار جديد للرؤية (`1.x`). ما تغيّرش الرؤية المجمّدة بصمت.

## 1. الثوابت (لا تُكسر)
- **تسليم الملفات كاملة 100% وبأوامر التيرمينال:** ممنوع إعطاء المالك أجزاء كود أو توجيهات تعديل يدوي لأسطر. أي ملف يتغير يُسلّم كاملاً بنسبة 100% مع مساره، ومرفقاً بأوامر الـ Git الجاهزة للنسخ في التيرمينال خطوة بخطوة.
- **مجاني بالكامل ومن غير كارت:** Firebase على Spark فقط (Auth + Firestore + Rules). **ممنوع** Blaze وCloud Functions وStorage وExtensions. GitHub Pages للواجهة، وGitHub Actions كـ Worker، وApps Script جسر Google Sheets والنسخة الاحتياطية فقط.
- **حصص Spark:** حوالي 1 جيجا تخزين، 50 ألف قراءة و20 ألف كتابة في اليوم. أي ميزة لازم تحسب أثرها على القراءات والكتابات. **راجع الحصص الحالية بالبحث قبل الاعتماد** (بتتغير).
- **ريبو عام:** ممنوع أي سر أو بيانات حقيقية (توكنات، عنوان Traccar، إحداثيات المواقع، أرقام تليفونات، أجهزة، بيانات سائقين). الأسرار في GitHub Secrets/Script Properties. القيم الافتراضية في الكود، والبيانات في Firestore.
- **الإعدادات أولًا:** لا ثوابت مدفونة. كل شيء له إدخال في **سجل الإعدادات (Registry)** والمالك يغيّره من المنصة. الحد: خوارزمية تحليل جديدة تمامًا = كود.
- **الاحتساب الأساسي من الـ GPS.** إدخال السائق/الخلاطة/الجراج بيانات مساندة للمطابقة حتى يعتمدها المسؤول.
- **الفترة المقفولة لا تتغير** (لقطة نهائية). التصحيح بعدها = تسوية تُضاف لأول فترة مفتوحة. فتحها بصلاحية وسبب.
- **التصميم:** الاتجاه الهادئ (مرجع `design/previews/Design-System-Preview-v0.3.0-draft.html`)، RTL، أرقام إنجليزية، فاتح/داكن، mobile-first، PWA، قوائم اختيار مخصّصة (مش native)، حركة قصيرة تحترم «تقليل الحركة».
- **الصلاحيات:** Super Admin وحده يعدّل ويقفل ويفتح حاليًا؛ المفاتيح `report.edit`, `period.close`, `period.open`, `adjustment.create/approve`, `import.upload` قابلة للمنح من المنصة.
- **Version control على كل حاجة:** SemVer للكود، `schemaVersion` للبيانات، `rulesVersion` للقواعد، `apiVersion`، إصدارات للوثائق والإعدادات والتخطيطات.
- **الحوار مع المالك:** عامية مصرية بسيطة، إجابة مباشرة، قرار واحد في المرة، ولا تفترض لما تكون الإجابة تأثيرها كبير.

## 2. الحالة الحالية (Current State)
**آخر تحديث:** 05/11/2026 · **المرحلة:** M1 · **الإنجاز العام:** 10 من 70 مهمة.

**اللي خلص:**
- **T0.1 إلى T0.6 (المرحلة M0 كاملة 100%):** الريبو محمي، الأمان مفعل، الهيكل مكتمل، 60 ملف ADR مسجلة، المعاينات والهوية معتمدة، الـ CI يعمل بنجاح، وبروتوكول التسليم مثبت بالملفات الكاملة وأوامر التيرمينال.
- **T1.1 (Spike S-1):** تم التحقق العملي بنجاح تام من قدرة GitHub Actions runners على الاتصال بسيرفر Traccar الداخلي عبر HTTP واستيثاق وسحب قائمة الأجهزة بكود 200 دون حظر شبكي، وتأكيد فرضية ADR-005.
- **T1.2 (Spike S-2):** تم التحقق العملي بنجاح تام من تهيئة Firebase Admin SDK وكتابة وقراءة وحذف مستندات Firestore على خطة Spark المجانية، والتأكد من حظر وقواعد الأمان للوصول غير المصرح به (403 PERMISSION_DENIED)، وتأكيد ADR-004 وADR-010.
- **T1.3 (Spike S-6):** تم التحقق العملي بنجاح تام من إدارة المستخدمين وإنشاء الحسابات وتعيين الأدوار عبر Custom Claims وتوليد روابط استعادة الباسورد، وإثبات أن Custom Claims توفر 100% من قراءات الـ Rules (صفر قراءات) لضمان البقاء تحت حصة Spark المجانية.
- **T1.4 (Spike S-4):** تم إجراء Benchmark كامل لتحليل 65 عربية بـ 65,000 نقطة GPS وأثبتت التجربة أن المعالجة تتم في أقل من ثانية واحدة (باستهلاك ذاكرة أقل من 30MB)، وتم توثيق معمارية مقاومة تأخير الـ cron عبر حقل `lastSyncTime`.

**جارٍ:** T1.5 (Spike S-3: حسم وتوثيق مكان كاش نقاط المسار وحماية مساحة الـ 1 جيجا في Spark).

## 5. بروتوكول التحديث بعد كل مهمة
1. تأكد أن **معيار القبول** اتحقق فعليًا (اختبار/تشغيل/لقطة)، مش مجرد كتابة كود.
2. غيّر حالة المهمة (✅ أو ⛔ مع السبب).
3. حدّث **القسم 2**: ما خلص + أي ملفات جديدة + أي قرار جديد (برابط ADR).
4. حدّث **القسم 3** بالخطوة التالية بخطوات دقيقة (مين يعمل إيه، وأي ملف يترفع وأين).
5. حدّث ترويسة الملف: `lastUpdated`، `currentMilestone`، `currentTask`، وزوّد `frameworkVersion`.
6. أضف سطرًا في **القسم 8**.
7. **الملفات كاملة 100% دائماً:** تسليم الملفات المعدلة كاملة مع مساراتها للنسخ والاستبدال المباشر بدون أجزاء مبتورة أو طلب تعديل يدوي.
8. **أوامر Git بالتيرمينال جاهزة للنسخ خطوة بخطوة:** إنشاء الفرع، commit، push، وpull على main بعد الدمج.
9. ما تبدأش المهمة التالية قبل ما المالك يؤكد.

## 6. تعريف الإنجاز (Definition of Done)
- **كود:** يعمل، له اختبارات، مراجَع بـ PR، من غير أسرار، وكل ثابت له إعداد في السجل.
- **واجهة:** تعمل فاتح/داكن/موبايل/ديسكتوب، RTL، أرقام إنجليزية، حركة تحترم «تقليل الحركة»، وتتجنب `<select>` الأصلي.
- **بيانات:** `schemaVersion` + migration + اختبار Rules + حساب أثر القراءات والكتابات.
- **قرار:** ADR + سطر في سجل القرارات.
- **الكل:** CHANGELOG محدّث، والإطار محدّث (القسم 5)، والملفات كاملة 100%.

## 7. نتائج الـ Spikes المعتمدة
- **Spike: S-1** | **التاريخ:** 05/11/2026 | **المنفّذ:** Claude + المالك (C+O)
  - **الفرضية:** هل تستطيع GitHub Actions runners الاتصال بسيرفر Traccar الداخلي للشركة عبر HTTP وسحب البيانات دون حظر شبكي أو جدار ناري؟
  - **ما اتعمل بالظبط:** تم إعداد Secrets (العنوان وبيانات الدخول) وإنشاء مسار عمل `spike-s1-traccar.yml` وسكريبت فحص اتصال Node.js لاختبار الوصول لنقطة `/api/server` واستيثاق وسحب قائمة الأجهزة `/api/devices`.
  - **النتيجة:** ✅ نجح بالكامل.
  - **الأرقام:** استجاب السيرفر في ~10 ثوانٍ (إجمالي الـ Action استغرق 25 ثانية)، وسحب قائمة الأجهزة بكود 200 بنجاح.
  - **القرار:** اعتماد GitHub Actions كـ Worker رسمي لسحب بيانات Traccar (تأكيد فرضية ADR-005).
  - **ADR:** ADR-005

- **Spike: S-2** | **التاريخ:** 05/11/2026 | **المنفّذ:** Claude + المالك (C+O)
  - **الفرضية:** هل يعمل Firebase Admin SDK لكتابة وقراءة Firestore من GitHub Actions على خطة Spark المجانية بدون كارت وبدون Blaze، وهل ترفض Firestore Rules الوصول غير المصرح به؟
  - **ما اتعمل بالظبط:** تم إعداد مشروع Firebase وقاعدة بيانات Firestore بنمط الإنتاج واستخراج مفتاح الخدمة وتمريره كـ Secret باسم `FIREBASE_SERVICE_ACCOUNT`. تم تشغيل سكريبت `s2-firestore-test.js` لاختبار الكتابة، القراءة، الحذف، ومحاولة الوصول غير المصرح به عبر REST.
  - **النتيجة:** ✅ نجح بالكامل.
  - **الأرقام:** تمت تهيئة Admin SDK، وكتابة مستند وقراءته وحذفه بنجاح خلال 22 ثانية، وحظر الوصول غير المصرح به بكود [403 PERMISSION_DENIED].
  - **القرار:** اعتماد Firebase Spark كقاعدة بيانات معتمدة وتأكيد ADR-004 وADR-010.
  - **ADR:** ADR-004, ADR-010

- **Spike: S-6** | **التاريخ:** 05/11/2026 | **المنفّذ:** Claude + المالك (C+O)
  - **الفرضية:** هل يمكن إدارة حسابات المستخدمين وتعيين أدوارهم وتوليد روابط استعادة كلمة السر عبر Admin SDK دون تسجيل خروج الأدمن، وكيف نحمي حصة القراءات اليومية (50 ألف) من تكلفة `get()` في Firestore Rules؟
  - **ما اتعمل بالظبط:** تم تفعيل Firebase Authentication وتشغيل سكريبت `s6-users-test.js` عبر GitHub Actions لاختبار إنشاء مستخدم بدور وتوليد رابط إعادة تعيين كلمة المرور، وتحليل تكلفة القراءات، وتنظيف حساب الاختبار.
  - **النتيجة:** ✅ نجح بالكامل.
  - **الأرقام:** استغرق التنفيذ 19 ثانية. إثبات أن Custom Claims (`request.auth.token.role`) تستهلك صفر قراءات (0 Reads) في Rules وتوفر 100% من استهلاك قراءات الـ Rules مقارنة بـ `get()` التي تستهلك آلاف القراءات يومياً.
  - **القرار:** اعتماد إدارة المستخدمين عبر Admin SDK وتضمين الأدوار في Custom Claims حصرياً لحماية حصة Spark المجانية.
  - **ADR:** ADR-013, ADR-015

- **Spike: S-4** | **التاريخ:** 05/11/2026 | **المنفّذ:** Claude + المالك (C+O)
  - **الفرضية:** ما هو زمن تحليل دورة كاملة لـ 65 عربية (65,000 نقطة GPS) في Node.js، وكيف يتعامل النظام مع تأخيرات جدولة cron في GitHub Actions؟
  - **ما اتعمل بالظبط:** تم تشغيل سكريبت `s4-cron-benchmark.js` لاختبار سرعة تحليل أسطول كامل مكون من 65 عربية بـ 65 ألف إشارة GPS، وقياس استهلاك الذاكرة وتوثيق معمارية التزامن الزمني.
  - **النتيجة:** ✅ نجح بالكامل.
  - **الأرقام:** استغرق الـ Job بالكامل 7 ثوانٍ فقط (زمن تشغيل الـ Action الكلي 11 ثانية)، معالجة الـ 65 عربية استغرقت أقل من 200ms، واستهلاك الذاكرة أقل من 30MB (أقل من 1% من قدرة السيرفر).
  - **القرار:** اعتماد معمارية GitHub Actions Worker لمعالجة الأسطول بالكامل بفضل سرعته الفائقة، وتثبيت قاعدة الاعتماد على `lastSyncTime` لضمان عدم ضياع أي بيانات مع تأخيرات الـ cron.
  - **ADR:** ADR-005
